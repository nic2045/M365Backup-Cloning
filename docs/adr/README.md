# Architecture decisions

| ADR | Title | Status |
|---|---|---|
| [0001](0001-the-dev-tenant-stack-reads-with-utcm-and-applies-with-microsoft365dsc-to-dev-only.md) | The Dev tenant stack reads with UTCM and applies with Microsoft365DSC to Dev only | Accepted |
| [0002](0002-the-toolkit-is-a-generic-tool-set-with-one-web-instance-per-customer.md) | The toolkit is a generic tool set with one web instance per customer (own stack, OpenAPI, jobs in own process, roles and audit, no call between applications) | Accepted |
| [0003](0003-persona-groups-and-naming-scheme-for-conditional-access-and-the-dev-tenant.md) | Persona groups and naming scheme for Conditional Access and the Dev tenant (static empty copies, test users and admins only; follows the Microsoft Zero Trust CA paper) | Proposed |
| [0004](0004-the-desired-state-lives-as-code-in-a-private-configuration-repository-of-the-operator.md) | The desired state lives as code in a private configuration repository of the operator (Prod export to files, Dev built only from it, drift as report, no write path to Prod) | Accepted |
| [0005](0005-the-factory-reset-is-the-one-deleting-run-align-by-default-full-on-purpose.md) | The factory reset is the one deleting run: Align (only Dev-only objects) by default, Full on purpose; protection list incl. Prod Global Administrators, two confirmations, Graph allow list, controlled rebuild | Accepted; devices "listed only" superseded in part by 0007 |
| [0006](0006-everything-is-copied-unless-it-is-on-the-exclusion-list.md) | Everything is copied unless it is on the exclusion list (generic handling, exclusion list as data, special handling only for safety) | Accepted |
| [0007](0007-devices-in-the-reset-are-kept-unless-an-action-is-chosen.md) | Devices in the reset are kept unless an action is chosen (Keep, Remove, Retire; Wipe only with Dev.AllowDeviceWipe; protected prefixes and users; device actions last) | Accepted |
| [0008](0008-the-web-api-wraps-the-core-files-in-a-versioned-envelope.md) | The web API wraps the core files in a versioned envelope (one schema file, OpenAPI 3.1 read routes, contract first, no secrets) | Accepted; the value of `schemaVersion` superseded by 0009 |
| [0009](0009-the-core-files-have-one-shape-and-no-full-tenant-id.md) | The core files have one shape and no full tenant ID (header in every file, time outside the plan hash, one summary and licence core, tenant as hash, closed lists, older plans refused; schema version 2) | Accepted |
| [0010](0010-the-web-instance-signs-in-with-entra-id-app-roles-and-a-local-fallback.md) | The web instance signs in with Entra ID app roles and a local fallback (OIDC code flow with PKCE, API checks every token, roles Reader/Applier/Resetter, local account only from loopback and off by default, scrypt hash, server-side sessions with CSRF) | Accepted; role of the local account (point 4) superseded by 0016 |
| [0011](0011-the-web-interface-follows-fluent-2-with-a-workflow-menu-and-guided-next-steps.md) | The web interface follows Fluent 2 with a workflow menu and guided next steps (Fluent 2 tokens in own CSS, Fluent UI System Icons, no Microsoft product logos, next step from API data only, readable local times, WCAG 2.2 AA) | Accepted; navigation (point 4) and "read only" superseded by 0012 |
| [0012](0012-the-web-interface-starts-jobs-and-is-organised-by-goals-and-areas.md) | The web interface starts jobs and is organised by goals and areas (menu Goals/Areas/History, Intune first; one plan with an area scope; jobs in own process with state in files; roles from one table; plan hash and typed Dev tenant checked by API, runner and script; wipe stays with the script) | Accepted; sign-in of the runner (point 7) superseded by 0013 |
| [0013](0013-web-jobs-sign-in-with-az-accounts-instead-of-own-token-code.md) | Web jobs sign in with Az.Accounts instead of own token code (certificate, process scope, raw token only because the core takes one token per tenant and reads Prod and Dev in one run; no own token code) | Accepted |
| [0014](0014-intune-backup-and-change-history-with-intunecd.md) | Intune backup and change history with IntuneCD (backup only, never its update; token on stdin; both tenants into the private configuration repository, replaced only when both succeeded; one commit per run, no push; changed paths and counts in History; job and page *Intune changes*) | Accepted |
| [0015](0015-intune-backup-leaves-scripts-out-by-default.md) | Intune backup leaves scripts out by default (`IncludeScripts` to back them up; no push; Conditional Access never) | Accepted |
| [0016](0016-the-web-app-starts-with-one-command-and-the-local-account-is-break-glass-only.md) | The web app starts with one command, and the local account is a break-glass account for management only (`Start-M365CloningWeb.ps1`, `web.settings.psd1`, token secret in `web.local`, local account role Reader only, enforced by script, interface and API) | Accepted |
